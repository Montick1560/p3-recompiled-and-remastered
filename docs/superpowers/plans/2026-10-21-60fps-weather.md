# 60 fps weather (Ton and Kan rain + tailwind) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** At 60 fps (`PSPRECOMP_PATCHES=60fps`) the Rain and Tailwind that Ton and Kan bring in FEVER run at the same real-time speed and duration as at 30 fps.

**Architecture:** The 60 fps set renders every vblank, so any game logic that counts in frames instead of the vblank delta runs twice as fast (see `docs/superpowers/plans/2026-10-15-60fps.md`, "Known gaps"). The fix has two steps. First, locate the per-frame weather step(s) with a diagnostic hook and a 30-vs-60 memory probe. Second, pace them to 30 Hz from the game module with a `VblankPacer`, the same way the input update is already paced (`input_update_30hz` in `games/patapon3/runtime/hooks_main.cpp`). The pacing is active only with the 60fps set, and an env switch allows A/B. Bonus (user, 21 Oct: "agrega las animaciones smooth también para la lluvia y el viento, si es que se puede"): where the moving state is float, run the step every vblank and halve its advance instead of skipping it, so the rain and wind move at 60 Hz at the 30 fps speed.

**Tech Stack:** C++20 runtime and game module (`psprecomp/`), ninja + ctest, Python 3 tools in `build/tools/` (outside the repo), debug socket on port 9998.

**Spec:** No separate design doc. The user's request (2026-10-21) is the spec:
> "Deberías jugar usando la savedata de Edson, la que tiene cerca de 1800 horas, en el Campo de los Gigantes, como está ahorita la savedata, podrías sacar el viento a favor y la lluvia, esos dos recursos van al doble de tiempo, empecemos un arreglo para esos dos."

## Review Focus

1. **Paused game (START menu) during rain at 60 fps:** the paced step must not resume early or run twice on unpause. Expected: the remaining duration after unpause is the same as at 30 fps. Task 5 Step 3 measures one pause.
2. **Game slowing down on its own (heavy battle, two vblanks per frame):** `VblankPacer` then runs every frame, so the weather must still be at 1× speed, not 0.5×. Expected: rain and wind speed within 10 % of 30 fps. Covered by `VblankPacer` semantics, and Task 5 Step 3 checks the log for frames longer than 25 ms during the run.
3. **Weather that is not a Ton / Kan skill (stage weather from the mission script: `setRainLevel` / `setWindLevel`):** if it shares the paced step, it also goes back to 30 fps speed, which is correct. Expected: no stage-weather mission gets slower than at 30 fps. Task 5 Step 4 checks one stage-weather mission if Task 2 finds one.
4. **The other two releases (vanilla, DxD 1.1.5b):** a hook at an address whose code differs would corrupt them. Expected: the hooked functions are byte-identical in all three releases, or the hook is skipped where they differ. Task 3 Step 1.
5. **Leaving a mission while it rains (back to the hideout):** the paced step must not keep stale state between missions. Expected: the next mission starts without rain. Task 5 Step 3 leaves one mission while it is raining.

### Task 4 (bonus): Smooth rain and wind at 60 Hz

Only if Task 2 found the moving state (particle positions, phase, wind streak offsets) as **float** words in guest memory. If the motion is computed each frame from an integer counter, there is no fractional state to advance by half. In that case skip this task, ledger `Ruling: weather smooth skipped — <why>`, and tell the user in the hand-off that it cannot be done this way.

**Files:**
- Create: `psprecomp/runtime/include/psp_half_step.h` (pure, generic, next to `psp_anim_blend.h`)
- Create: `psprecomp/runtime/tests/test_half_step.cpp` + CMake block next to `test_anim_blend` in `runtime/CMakeLists.txt`
- Modify: `psprecomp/games/patapon3/runtime/hooks_main.cpp` (the Task 3 hooks)
- Modify: `psprecomp/ARCHITECTURE.md` (the Task 3 weather paragraph)

**Interfaces:**
- Consumes: the Task 3 hooks and their word table (offset, float/int).
- Produces: `float psp_half_step(float before, float after, float max_jump)`; env `PSPRECOMP_P3_WEATHER_SMOOTH` (`0` = plain Task 3 pacing; default on with the 60fps set).

Idea: the step runs every vblank. After each call:
- every **float** word in the table is set to `before + (after - before) / 2`, so it advances half as far per vblank, which is the 30 fps speed at 60 Hz;
- every **integer** word (timers) is restored to `before` on the vblanks the Task 3 pacer says are not due, so durations stay exactly as in Task 3.

A particle that respawns jumps far (bottom to top, or a new random x). That jump must happen at once, not slide across the screen, so a change larger than `max_jump` is kept whole.

- [ ] **Step 1: Write the failing test `test_half_step.cpp`**

```cpp
CHECK(psp_half_step(10.0f, 12.0f, 50.0f) == 11.0f);      // normal advance: half
CHECK(psp_half_step(10.0f, 8.0f, 50.0f) == 9.0f);        // negative advance: half
CHECK(psp_half_step(270.0f, -10.0f, 50.0f) == -10.0f);   // respawn: whole jump kept
CHECK(psp_half_step(5.0f, 5.0f, 50.0f) == 5.0f);         // no change
CHECK(std::isnan(psp_half_step(1.0f, NAN, 50.0f)));      // garbage passes through untouched
```

Use the same `CHECK` style as `test_anim_blend.cpp`.

- [ ] **Step 2: Run it.** `ninja -C <build dir> test_half_step`. Expected: compile FAIL, `psp_half_step` not declared.

- [ ] **Step 3: Implement `psp_half_step` in `psp_half_step.h`.**
  - A non-finite `after` returns `after`.
  - `|after - before| > max_jump` returns `after`.
  - Otherwise return the midpoint.

  Add a header comment in the style of `psp_vblank_pacer.h`.

- [ ] **Step 4: Run it.** Expected: PASS.

- [ ] **Step 5: Use it in the hooks.**
  - With `PSPRECOMP_P3_WEATHER_SMOOTH` on, the Task 3 hook snapshots the table's words, calls the step **every** vblank, then writes back `psp_half_step` for float words. For int words, it writes back the snapshot on not-due vblanks.
  - Per word, `max_jump` = 4× the largest per-vblank advance measured at 60 fps in Task 2, written as a constant with that origin in the comment.
  - Skip any word whose address the step did not touch this call (before == after needs no write).

- [ ] **Step 6: Measure.** Two checks, at 60 fps, smooth on vs `PSPRECOMP_P3_WEATHER_SMOOTH=0`:
  - **Speed:** `weather_probe.py` rates of the float words are within 10 % of 30 fps.
  - **Smoothness:** `build/tools/anim_rate.py 9998 10 <x0 y0 x1 y1>` on a rain-only region (no units) reports about 2× the distinct frames per second of the paced version.

  Then take 4 consecutive screenshots and check that no particle smears or slides across the screen on respawn.

  If the speed is off by more than 10 % or particles smear, set the default to off, ledger it, and keep Task 3's pacing as the shipped behaviour.
