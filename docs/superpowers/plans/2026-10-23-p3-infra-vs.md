# VS search in infrastructure mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two parties in infrastructure mode pick VS and find each other, because a player can be in its hideout
room and a VS room at once, and room flags (HIDDEN, CLOSED) work as on PSN.

**Architecture:**
- The room server lets a connection join up to 4 rooms and applies room flags to set_internal, search and join.
- The runtime's single-room Matching2 state moves to a pure, tested module keyed by room id; the HLE uses it and
  forwards the flags.
- Then e2e: one party (the loop must stop), then two parties (the VS must start), recording the game's requests
  before fixing anything else.

**Tech Stack:** Python 3 stdlib (`tools/infra_server.py`, its `--selftest`), C++20 runtime (`runtime/`, ctest in
`build/rtw`), e2e driver `build/infra/two.py` + shell scripts (outside the repo).

**Spec:** `docs/superpowers/specs/2026-10-23-p3-infra-vs-design.md` (read its Evidence first).

## Review Focus

1. **A player drops while in two rooms:** both rooms get their own `member_left` / `room_destroyed`, nothing is
   left behind in `server.rooms`. Test `drop_leaves_every_room` (Task 1).
2. **Datagrams between players who share only the VS room** (different hideouts) still pass; players who share no
   room still cannot reach each other. Test `dgram_needs_a_shared_room` (Task 1).
3. **Owner leaves the hideout while the VS room stays:** the runtime keeps the VS room's peers and callback.
   Test `leave_keeps_other_rooms` (Task 2).
4. **Connection lost while in two rooms:** the client synthesizes `room_destroyed` once per room. Test
   `loss_destroys_every_room` (Task 2).
5. **The flag loop:** a hidden hideout never appears in the other party's search, and is found again after the game
   clears HIDDEN. Test `hidden_rooms_not_found` (Task 1).

### Task 1: Server — up to 4 rooms per connection, and room flags

**Files:**
- Modify: `tools/infra_server.py` (`Conn`, `op_create`, `op_join`, `op_leave`, `op_kick`, `op_set_internal`,
  `op_bound`, `op_search`, `match`, `leave_room`, `drop`, `on_datagram`, `on_stream`, `selftest`)

**Interfaces:**
- Produces (wire, used by Task 2):
  - `set_internal {room_id, bins?, flag_filter?, flag_attr?}`: `room.flag_attr = (room.flag_attr & ~filter) |
    (attr & filter)`.
  - `search {..., flag_filter?, flag_attr?}`: a room matches when `(room.flag_attr & filter) == (attr & filter)`
    and it is not HIDDEN.
  - `join` on a room with CLOSED or FULL -> ROOM_FULL.
  - `create`/`join` -> ALREADY_JOINED only for the same room; a 5th room -> SERVICE_UNAVAILABLE
    (`MAX_ROOMS_PER_CONN = 4`).
  - `leave`/`kick` with a `room_id` the connection is not in -> NO_SUCH_ROOM (as today).
- Server internals: `Conn.rooms: dict[int, Room]`; `leave_room(conn, room, cause, opt)` takes the room;
  `share_room(a, b) -> bool`.

### Task 2: Runtime — rooms by id, flags sent

**Files:**
- Create: `runtime/include/net/np2_rooms.h`, `runtime/src/net/np2_rooms.cpp` (pure),
  `runtime/tests/test_np2_rooms.cpp`
- Modify: `runtime/src/hle/psp_hle_np_matching2.cpp` (`State`, `enter_room`, `handle_event`, `post_room_event`,
  signaling, `hle_sceNpMatching2LeaveRoom`, `SetRoomDataInternal`, `SearchRoom`, `SignalingGetConnectionStatus`,
  `leave_server`), `runtime/include/net/infra_client.h`, `runtime/src/net/infra_client.cpp` (`room_id_` -> a set),
  `runtime/tests/test_infra_client.cpp`, `runtime/CMakeLists.txt`, `ARCHITECTURE.md`

**Interfaces:**
- Consumes: Task 1's wire fields (`flag_filter`, `flag_attr` on `set_internal` and `search`).
- Produces, `net/np2_rooms.h`, namespace `np2`:
  - `struct Peer { uint32_t vip = 0; uint16_t port = 0; };` (moves out of the HLE file)
  - `struct RoomCallback { uint32_t cb = 0, arg = 0; };`
  - `class Rooms` (not thread-safe; the HLE keeps it under its mutex):
    - `void enter(const nlohmann::json& room, RoomCallback cb);` (room = the server's `internal()` object: `id`,
      `me`, `members[{member_id, vip, port}]`)
    - `bool has(uint64_t room) const;` `void leave(uint64_t room);` `void clear();`
    - `std::vector<uint64_t> ids() const;`
    - `void member_joined(uint64_t room, uint16_t id, Peer p);` `void member_left(uint64_t room, uint16_t id);`
    - `void signaled(uint64_t room, uint16_t id, Peer p);` (ESTABLISHED: records the peer)
    - `bool peer(uint64_t room, uint16_t id, Peer* out) const;` (false for an unknown room or member, or vip 0)
    - `RoomCallback callback(uint64_t room) const;` (`{0, 0}` for an unknown room)
- `infra::Client`: `std::set<int64_t> rooms_` replaces `room_id_`; `lost()` synthesizes one `room_destroyed` per
  room; a `create`/`join` answer adds, `leave` (by its `room_id`) and a `room_destroyed`/`kicked` event remove.
- HLE: events for a room not in `Rooms` are ignored (as today for a foreign room id); the room event and
  signaling callbacks get the event's own room id; SetRoomDataInternal sends `flag_filter`/`flag_attr` (drop the
  "not sent" line); SearchRoom sends `flag_filter` (@0x18) and `flag_attr` (@0x1C) when the filter is non-zero.
