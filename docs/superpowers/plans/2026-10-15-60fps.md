# 60 fps (Patapon 3) — notes and status

Written 2026-10-15 (Opus 5.5, overnight session). Status: implemented, opt-in
(`PSPRECOMP_PATCHES=60fps`); pending: the user plays with `jugar_60fps.bat`.

## What runs

- **Patch sets** (generic): `[[patch_sets]]` in `games/<id>/game.toml` = instruction words +
  code caves. `psprecomp recompile` re-emits every function holding a patched word from the
  patched bytes (`<name>__ps_<set>`, mid-entries get wrappers) into `patch_sets.cpp`, plus
  the caves (`PATCH_<set>_<addr>`). `PSPRECOMP_PATCHES=<set>` registers them over the
  dispatch table at boot (`runtime/src/psp_patch_sets.cpp`). The batches are byte-identical
  with or without sets (checked by regenerating into a temp dir and diffing).
- **`60fps` set**: Madwig's "60 FPS Patch v3" CWCheat for UCES-01421 (efonte/patapon-re
  `CWCheats/60 FPS Patch v3 [P3] [EUR].ini`, copy in `build/refs/patapon-re/`; its OFF block
  lists the original words, which match ours). All 10 patched words hold the expected original words in the DxD EBOOT
  (read from `INFN00001_EBOOT.BIN`): the vblank-wait `bnez` in FUN_0883E674, five words of
  the sample-merge exits in FUN_0883D434 (two branch-likely pairs and one `beq`; the relay
  note called the third word `li a2,0`: wrong), and two `mul.s`/`add.s` pairs in
  FUN_088FA9D0 rerouted through the cave at 0x08800C00 that halves the unit advance.
- **Input at 30 Hz** (game module, `games/patapon3/runtime/hooks_main.cpp`): the game counts
  input in frames in two places: the pad block (FUN_0883D434: 20-frame repeat delay,
  6-frame repeat, held counters) and the input object (FUN_08852628/08852984: its own
  counters, delay +180, interval +184). With the cheat alone a 120 ms tap moves the
  language menu two rows and the hideout map two buildings. PPSSPP 1.20.4 with the same
  cheat does the same on the hideout map (checked: R held 7 frames -> Cuartel to Obelisco).
  The module runs FUN_08851EC8 (pad block + input object) at most once per two vblanks
  (`VblankPacer`) and on the frame in between clears only the edge words. Language menu
  and hideout map now match the 30 fps runtime for 40-1000 ms holds.

## Known gaps / next

- Anything else the game advances per frame without the vblank delta (the engine stores the
  vblank delta at frame object +76, but only a few functions read it) runs twice as fast.
  Not seen yet in menus, hideout or the training mission; watch for it in other missions,
  FEVER, minigames, cutscenes.
- Weather (rain and wind, 2026-10-21): done. The weather objects' updates (FUN_089010DC rain,
  FUN_08902EE0, FUN_08903F40) move particles by a fixed step per call; the module paces each
  object's update to 30 Hz with the skipped frame time banked (`PSPRECOMP_P3_WEATHER_30HZ=0`
  for A/B). Rain 56.8 -> 29.7 steps/s (30 fps: 29.7). See `2026-10-21-60fps-weather.md`.
  Smooth on top (`PSPRECOMP_P3_WEATHER_SMOOTH`): rain drawn half a step ahead on the frames in
  between (rain positions change 60 times/s instead of 30), wind ribbons stepped every frame with
  half the per-call advance (29.8 full steps/s).
- Hideout props / scripts (2026-10-21): the Silver Hoshipon floated twice as fast. Its motion is
  a script (read actor position, add a step, set it) run once per update of the script object
  (FUN_08909C7C, a1 = frame ticks); scripts also wait in frames (cmd_waitFrame). The module
  paces each script object to 30 Hz with the skipped frame time banked
  (`PSPRECOMP_P3_HIDEOUT_30HZ=0` for A/B). Star period 2.2 s -> 4.4 s (30 fps: 4.35-4.63). The
  owl on the Master Obelisk measured the same at 30 and 60 (bob 1.0 s, eyes 1.06 s). See
  `2026-10-21-60fps-hideout-anims.md`.
- Animation smoothness: done as a game-module hook, on by default with this set
  (`PSPRECOMP_P3_ANIM_SMOOTH`); see `2026-10-15-smooth-anim.md`. Army idle ~16 -> ~40 pose
  changes/s.
- Hideout place halo and Hero Gate sparkles (2026-10-21): speed already equal at 30 and 60
  (gate cycle 1.00 s, halo pulse ~1.07 s); their fades stepped because the pose blend skipped
  the bone alpha (+0x4C) and texture offset (+0xC0/+0xC4). Alpha now blended
  (`PSPRECOMP_P3_ANIM_SMOOTH_FADE=0` for A/B); see `2026-10-21-60fps-herogate-halo.md`. The
  texture offset was blended too at first and drew half-cell eyes on the Patapons (atlas
  flipbooks); it stays on whole frames.
- FEVER worm (2026-10-22): speed already equal at 30 and 60 (keys at 30/s body, 15/s head);
  it stepped because the mission overlay's motion player draw `0x08B72338` runs outside the
  smooth scope and draws at three clocks (+0x68, +0xA0, +0xA8). Scope hook on that overlay
  address + per-model clock + baked bone blend (`PSPRECOMP_P3_ANIM_SMOOTH_WORM=0` for A/B);
  see `2026-10-22-60fps-fever-worm.md`. [DL] dumps slow the game too much to measure
  time-based animation: the per-list values were identical at 30 and 60.
- Chest-room reward halo (2026-10-22): speed already equal at 30 and 60 (loop 2.0 s, pulse
  0.668 s); it held each frame 4 vblanks because the mission overlay's reward draw `0x08B4CB28`
  draws its two player blocks (item +0x78, halo +0xF8 clocks) outside any smooth scope. Scope
  hook on that overlay address with a per-kind clock table shared with the worm
  (`PSPRECOMP_P3_ANIM_SMOOTH_REWARD=0` for A/B); 15 -> ~47 changes/s (capture-limited); see
  `2026-10-22-60fps-chest-halo.md`.
- Mission script waits (2026-10-22): the mission-start countdown (TON, CHIN, KAN, Ya) and the
  march hints ran 2x (0.245 s per bubble vs 0.50 s; hints every 2 s vs 4 s) because mission
  scripts run every vblank and `cmd_waitFrame` counts runs. A wait that has just started is made
  twice as long (hideout excluded, its scripts are paced); scripts are not paced
  (`PSPRECOMP_P3_SCRIPT_WAIT_30HZ=0` for A/B); see `2026-10-22-60fps-mission-countdown.md`.
- Patch sets cover the main image only; words inside the overlay window are rejected.
