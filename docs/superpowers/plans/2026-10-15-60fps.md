# 60 fps (Patapon 3) — notes and status

Written 2026-10-15 (Opus 5.5, overnight session). Status: implemented, opt-in
(`PSPRECOMP_PATCHES=60fps`); pending: the user plays with `jugar_60fps.bat`.

## What runs

- **Patch sets** (generic): `[[patch_sets]]` in `games/<id>/game.toml` = instruction words +
  code caves. `psprecomp recompile` re-emits every function holding a patched word from the
  patched bytes (`<name>__ps_<set>`, mid-entries get wrappers) into `patch_sets.cpp`, plus
  the caves (`PATCH_<set>_<addr>`). `PSPRECOMP_PATCHES=<set>` registers them over the
  dispatch table at boot (`runtime/src/psp_patch_sets.cpp`). The batches are byte-identical
  with or without sets (checked by regenerating into a temp dir and diffing).
- **`60fps` set**: Madwig's "60 FPS Patch v3" CWCheat for UCES-01421 (efonte/patapon-re
  `CWCheats/60 FPS Patch v3 [P3] [EUR].ini`, copy in `build/refs/patapon-re/`; its OFF block
  lists the original words, which match ours). All 10 patched words hold the expected original words in the DxD EBOOT
  (read from `INFN00001_EBOOT.BIN`): the vblank-wait `bnez` in FUN_0883E674, five words of
  the sample-merge exits in FUN_0883D434 (two branch-likely pairs and one `beq`; the relay
  note called the third word `li a2,0`: wrong), and two `mul.s`/`add.s` pairs in
  FUN_088FA9D0 rerouted through the cave at 0x08800C00 that halves the unit advance.
- **Input at 30 Hz** (game module, `games/patapon3/runtime/hooks_main.cpp`): the game counts
  input in frames in two places: the pad block (FUN_0883D434: 20-frame repeat delay,
  6-frame repeat, held counters) and the input object (FUN_08852628/08852984: its own
  counters, delay +180, interval +184). With the cheat alone a 120 ms tap moves the
  language menu two rows and the hideout map two buildings. PPSSPP 1.20.4 with the same
  cheat does the same on the hideout map (checked: R held 7 frames -> Cuartel to Obelisco).
  The module runs FUN_08851EC8 (pad block + input object) at most once per two vblanks
  (`VblankPacer`) and on the frame in between clears only the edge words. Language menu
  and hideout map now match the 30 fps runtime for 40-1000 ms holds.

## Known gaps / next

- Anything else the game advances per frame without the vblank delta (the engine stores the
  vblank delta at frame object +76, but only a few functions read it) runs twice as fast.
  Not seen yet in menus, hideout or the training mission; watch for it in other missions,
  FEVER, minigames, cutscenes.
- Animation smoothness: measured with screenshot bursts (49 captures/s) on an idle army in
  a mission: ~22 pose changes/s at 30 fps and the same at 60 fps, so character animations
  are not smoother at 60 (camera, scrolling and effects are). Leads for the next session:
  motion components hang off unit +200 (PAC handlers getMotionFrameRate 0x08912C70 /
  setMotionFrameRatio 0x08912BA8, ratio float at +168); FUN_0887AEFC truncates
  frame * ratio to an int before setting the motion time (FUN_0888E038 -> FUN_08878A18);
  the unit update FUN_0888E7FC takes a float dt in f12. Writing the manager's interval
  (+7520 = 2) / fps (+7524 = 30.0) to 1 / 60.0 at run time changed nothing visible. Tayo
  Fox's "3 bytes" hint is still unverified. Function names: efonte/patapon-re
  `PPSSPP sym/ppsspp_p3_UCES01421_913_func_names.sym` (copy in build/refs/patapon-re/).
- Patch sets cover the main image only; words inside the overlay window are rejected.
