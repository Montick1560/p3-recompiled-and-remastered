# Beta 1 of infrastructure mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A weekend beta of the online mode for ~25 invited players: a public sign-up queue the user raffles
invitations from, invite codes, a server-enforced window (23 Oct 21:00 - 25 Oct 23:59 CDMX), launcher and exe that
stop after it, metrics, problem reports, a load test, and a package on R2 with an email template the user sends.

**Architecture:**
- `tools/infra_server.py` (one file, copied as is to the server machine) gains a beta config (codes, window,
  minimum protocol), HTTP status/check routes on its WebSocket listener and a SQLite metrics writer thread.
- A second stdlib service `tools/beta_report_server.py` takes reports (launcher button and `report.montick.app`
  form) and sign-ups (`beta.montick.app`) into the same SQLite file; `tools/beta_cola.py` (run by the user on the
  server machine) draws invitees from the queue and adds their codes to the live server config.
- The runtime sends `proto` and `invite` in its login and, in beta builds, refuses to start after the end date.
- The launcher asks for the code, gates Start on the server's status, and sends reports with the log attached.

**Tech Stack:** Python 3 stdlib (http.server, sqlite3, zlib), C++20 runtime (ctest in `build/rtw`), launcher Tauri 2
(Rust `ureq`, `sha2`; React + vitest) in `C:/Users/torso/Documents/deco/launcher`.

**Spec:** `docs/superpowers/specs/2026-10-23-p3-beta-1-design.md`

## Review Focus

1. **A code typed differently** (`p3-k7qf-2mxd`, spaces, missing dashes) must be accepted: `code_normalized`
   (Task 1), Rust `normalize_code` test (Task 4).
2. **The server machine restarts mid-beta**: codes, window and metrics come back from files; a session counted
   at the restart is closed with reason `server_stop`: `metrics_survive_restart` (Task 2).
3. **Server unreachable from the launcher during the window** (tunnel down): Start still allowed while the
   embedded window says open; after the embedded end, blocked: `gate_offline_inside_window`,
   `gate_offline_after_end` (Task 4).
4. **A huge or hostile report** (10 MB body, HTML in text fields, flood from one address): refused or escaped,
   never stored raw into the summary HTML: `report_limits`, `summary_escapes_html` (Tasks 5, 6).
5. **Two invitees behind one home IP** both play: per-address limit counts connections (4), not codes:
   `two_codes_one_address` (Task 1).
6. **The same person signs up twice** (`Ana@Mail.com ` and `ana@mail.com`) or a bot fills the hidden field: one queue
   row, same answer to the person, bot row never stored: `queue_dedup`, `queue_honeypot` (Task 5); a draw never picks
   someone twice across batches: `draw_skips_invited` (Task 9).
