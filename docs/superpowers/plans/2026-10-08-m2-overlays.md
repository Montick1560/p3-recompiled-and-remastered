# M2 — Overlays (bancos de código) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Recompilar `OL_Azito.bin`, `OL_Mission.bin` y `OL_Title.bin` como bancos de funciones que el runtime activa según el overlay cargado en la ventana 0x08ABB180–0x08BC6480.

**Architecture:** (1) `scripts/overlay_elf.py` arma un ELF "combinado" (EBOOT + overlay en su ventana) que el pipeline existente analiza sin cambios (probado: 13/13 bloques verificados, 497 funciones en la ventana de Azito). (2) `recompile --bank <name>` emite solo las funciones de la ventana, envueltas en `namespace <name>`, con una tabla que se registra sola (`psp_overlay_register_bank`) y una librería CMake OBJECT. (3) El `main` excluye la ventana (`[overlays] window` en game.toml) — hoy tiene 4,368 "funciones" basura ahí. (4) El runtime resuelve en `psp_on_lookup_miss` las direcciones de la ventana contra el banco cuyo id coincide con la cabecera MWo3 en memoria, verificando una huella FNV-1a 64 de cabecera+texto una vez por activación; si no coincide: error explícito y abort.

**Tech Stack:** Rust (psp-cli/psp-emitter), C++17 runtime, CMake OBJECT libraries, Python 3 (stdlib).

**Spec:** `docs/superpowers/specs/2026-10-07-patapon3-native-port-design.md` §7.

## Global Constraints
- Autor de commits `Patapon Community`, sin `Co-Authored-By`.
- Ventana: `0x08ABB180`..`0x08BC6480` (fin del PT_LOAD principal original). Cabecera MWo3: `[magic, id, load, text_size, data_size, bss_size, ctor_start, ctor_end]`.
- Nada de datos del juego en git (`data/`, `*.bin`, `*.elf` combinados viven en `deco/build` o `data/`).
- Todo lo genérico (bancos, ventana) en runtime/src y crates; lo de Patapon 3 solo en `games/patapon3/`.

## Review Focus
1. Dos bancos con las mismas direcciones (los tres overlays comparten ventana) no deben chocar al enlazar → namespaces distintos; prueba: build con los 3 bancos.
2. Overlay en memoria que no coincide con el banco compilado (mod cambiado sin recompilar) → abort con mensaje claro; prueba unitaria `HASH_MISMATCH`.
3. Dirección de la ventana sin overlay cargado (magic ≠ MWo3) → miss normal, sin crash; prueba unitaria `NO_BANK`.
4. Llamadas desde la ventana hacia el main → siguen resolviendo por la tabla del main (no se excluyen); cubierto por la corrida del juego.
5. Varios hilos resolviendo a la vez durante el cambio de overlay → activación protegida por mutex; revisión.
