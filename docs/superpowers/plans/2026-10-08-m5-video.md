# M5 — Video (PSMF + sceMpeg via FFmpeg) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:test-driven-development per task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Patapon 3's movies (PSMF files embedded in `DATA_CMN.BND`, e.g. the opening movie after the terms screen) play: H.264 frames decoded into the game's guest buffer through `sceMpegAvcDecodeYCbCr`/`sceMpegAvcCsc` (or `sceMpegAvcDecode`), audio through `sceMpegAtracDecode`, and the movie ends so the game reaches the title screen.

**Why now (moved ahead of M3/M4):** the game blocks after the terms screen. Its movie thread calls `scePsmfSetPsmf` → `scePsmfGetNumberOfSpecificStreams` (stub returns 0) and then idles forever; the main thread draws a black textured quad (the video surface) each frame.

**Architecture:**
- `runtime/src/hle/psp_psmf.{h,cpp}` (header next to existing hle headers): pure PSMF header parser (PPSSPP `Core/HLE/scePsmf.cpp` `Psmf` class: version, stream offset/size, stream table — AVC/ATRAC/PCM streams with type/channel, video width/height, presentation timestamps).
- `runtime/src/hle/psp_mpeg_demux.{h,cpp}`: MPEG-PS demuxer for the ringbuffer data (PPSSPP `Core/HW/MpegDemux.cpp`) — extracts AVC elementary stream and ATRAC3plus audio AUs with PTS.
- `runtime/src/hle/psp_media_engine.{h,cpp}`: FFmpeg-backed decoder (PPSSPP `Core/HW/MediaEngine.cpp`): H.264 via libavcodec, colour conversion via libswscale to the PSP pixel formats (5650/5551/4444/8888) honouring the buffer width; ATRAC3plus audio via libavcodec's `atrac3p` decoder (simplest; independent of the sceAtrac task).
- `runtime/src/hle/psp_hle_mpeg.cpp`: `sceMpeg*` and `scePsmf*` HLE on top of the above, ported from PPSSPP `Core/HLE/sceMpeg.cpp` / `scePsmf.cpp` (ringbuffer struct in guest memory incl. the game's read callback, `sceMpegRingbufferPut` calling the guest callback, AU structs, `GetAvcAu`/`GetAtracAu` end-of-stream errors, YCbCr path). Replaces the stubs in `psp_hle_utility.cpp`.

**Tech Stack:** C++17, FFmpeg 7.1.1 LGPL shared (BtbN `autobuild-2025-06-30-13-55`, extracted at `C:/Users/torso/Documents/deco/tools/ffmpeg-7.1.1/ffmpeg-n7.1.1-54-g6400860b9d-win64-lgpl-shared-7.1/` with `include/`, `lib/*.dll.a`, `bin/*.dll`). ## Global Constraints
- Commits authored `Patapon Community`; NO `Co-Authored-By` trailer. Do not push.
- Generic runtime code only (no Patapon addresses). FFmpeg is optional at configure time: CMake option `PSPRECOMP_FFMPEG_DIR` (path to the package root); when absent the build still succeeds and the HLE reports no video streams (current behaviour). POSIX builds may use pkg-config for FFmpeg.
- The FFmpeg DLLs needed at runtime (avcodec, avutil, swscale, swresample) are copied next to `psprecomp_runtime.exe` by a POST_BUILD step on Windows.
- Guest pointers are masked/bounds-checked; malformed PSMF data → error codes, never a host crash.

## Review Focus
1. Ringbuffer semantics (packets, read callback invocation, available size) — wrong counts stall the game's feeder loop.
2. End of movie: `GetAvcAu` must return PPSSPP's "no data / end of stream" error once the stream is exhausted, so the game leaves the movie.
3. Output pixel format and buffer width from the game (`sceMpegAvcDecodeMode`/`Csc` args) — wrong stride garbles the frame.
4. Thread safety: movie thread decodes while the main thread renders.
5. Skipping a movie (START) must release decoder state cleanly.
