# Performance pass 1 (CPU / GPU / RAM) — plan

Date: 2026-10-11. Status: not started. Goal: lower CPU, RAM and driver overhead per instance
without changing what is drawn (4-player ad hoc on one PC and a future Android port are the
targets). Every step is measured before and after; the graphics tour is the regression check.

## Baseline (hideout, frozen save build/tour_save, one instance, Ryzen/NVIDIA desktop)

| Config | fps | CPU | RAM | GPU | GE ms/frame | draws/frame | binds/frame |
|---|---|---|---|---|---|---|---|
| scale 1, no pack | 30.0 | 36% of 1 core | 132 MB | — | 4.2 | ~1430 | ~1420 |
| scale 4 + HD pack (jugar.bat) | 30.0 | 46% of 1 core | 413 MB | 9% | 4.7 | ~1545 | ~1540 |

The game already runs at its native 30 fps with 10-20% CPU wait; the cost is per-draw overhead
and texture-pack memory, which multiplies with 4 instances.

## How to measure (before/after every task)

- `PSPRECOMP_PERF=1`: `[PERF]` line every 2 s (fps, ge_ms/frame, draws, binds, tex_hash_MB, cpu_wait).
- CPU/RAM: `Get-Process psprecomp_runtime` TotalProcessorTime over 5 s, WorkingSet64;
  GPU: `nvidia-smi --query-gpu=utilization.gpu,memory.used --format=csv`.
- Route: `TOUR_RT_PORT=9998 python build/tools/gfx_tour.py --only rt --keep --checkpoints
  gfx_hideout.json` (hideout) and `gfx_mission_r.json` (Campo de los Gigantes, storm + wind).
- Regression: full tour (`gfx_tour.py` + `gfx_score.py`), pixel scores must not get worse.
- Known tool gap: `land()` compares 480x272 reference frames, so at render scale > 1 it fails
  and keeps pressing buttons. Fix first: downscale `frame()` to 480x272 before `struct_diff`
  (or capture the 1x guest framebuffer).

## Tasks (one commit each, by expected gain)

1. **Draw batching (CPU, driver).** ~1500 GL draw calls/frame, each with a texture bind and its
   own VBO upload. (a) one persistent/orphaned VBO ring per frame instead of per-draw buffer
   uploads; (b) skip redundant GL state changes (texture already bound, same blend/depth/shader
   uniforms) with a shadow-state cache; (c) merge consecutive draws with identical state into
   one glDrawArrays. Expect the largest CPU win; verify draws/frame and GE ms/frame drop.
2. **Texture pack memory cap (RAM).** Keep decoded HD textures under a budget (e.g. 256 MB)
   with LRU eviction of GL textures and the decoded PNG cache; release pack PNG buffers after
   upload. Target < 250 MB per instance with the pack.
3. **Texture hash cost.** `tex_hash_MB/frame` 0.4-0.6: hash only on first bind per list (memo
   exists) and skip re-hashing textures whose guest memory was not written since (write
   generation per 4 KB page, or reuse PPSSPP's "frame-delayed" check for static textures).
4. **Light mode for secondary instances.** `PSPRECOMP_LIGHT=1`: scale 1, no pack, no audio,
   capped present rate; used by jugar_vs4.bat for players 2-4.
5. **Idle/wait behaviour.** Confirm the main thread sleeps (not spins) while waiting for vblank
   or GE work; check the 18-19 threads for busy loops (per-thread CPU time).
6. **Recompiled code.** Measure `psp_trace_checkpoint` cost per guest call (shared atomic ring
   on every function entry): make the ring/watch path cheaper or compile-time optional
   (`PSPRECOMP_TRACE_CHECKPOINTS`), keeping crash backtraces.

Out of scope here: 60 fps, widescreen, Android (separate plan: GLES 3 port of the renderer,
NDK ARM64 build, touch/gamepad input, perf targets from this pass).
